## 1. Meeting time

A member who cannot attend tells the team **at least 1 hour before** and reads the minutes.

## 2. Communication

Primary channel: **#team-bookbuddies**. Client contact goes through **Iid Maxamuud**.
We reply within **4** hours on weekdays. Anything urgent: **Text Messaging**.

## 3. How we decide

Routine calls: **Whoever owns the use case decides. Unless it is for a pull request in which the reviewers have final say**.
Anything affecting the whole team: **Discussed at the weekly meeting, majority, ties go to the project lead**.
A decision that survives the meeting is written down in **docs/Team_Decisions.md**.

## 4. How work is claimed

Work is divided **by use case, not by layer**. One member owns a use case end to
end: front end, back end, tests, and the pipeline.
Claiming: **Assign yourself the sub-issue and move the card. In general, you should pick sub-issues that are generally related to each other**.
Nobody is the "front-end person" or the "tester".

## 5. Git workflow and review

Coding conventions (naming, formatting, layout) live in `CLAUDE.md`, not here.
This clause is about how work moves.

Branch per sub-issue, named **convention, e.g. feat/42-short-slug, feat/ being feature and fix/ being bugfix for example**.
Never push to `main`. Every change arrives as a pull request.
A pull request needs **2 (Or more if people decide)** approving review(s) from someone who does not own the use case.
A reviewer reads the issue before the diff. Blocking a merge: **If a test case does not pass, code completely changes code from someone else's use case, if there are bugs when testing the use case, or special cases come up**.

## 6. Working with AI

We use **Claude Code**. Our charter lives in `CLADUE.md`.
Every member can explain any line submitted under their name.
We do not merge agent output that nobody has read.
Additional limits we agree on: **<anything else>**.

## 7. When someone does not deliver

First: **The team will attempt to communicate with the member to determine the reason for the delay and establish a recovery plan**. We attack the problem, not the person.
If it happens again: **The team will redistribute unfinished work and discuss and document the problem**.
Still unresolved: we escalate to our TA, then to the instructor. We escalate early.
